## Корінь проблеми — математичне виродження `get_mask_v2`

### Що відбувається

Файл: `SiamKPConvWithPriorUncertainty.py:60-112`.

Кроки:

1. **Геометричний пріор** `D = clamp(dist/3.0, 0, 1)`.
   - `pos_th = 3.0` метра. Після `GridSampling3D(size=1.0)` найближчі сусіди мають відстань ~0-1.5 м.
   - **D реально варіюється у [0, 0.5]**, несе сигнал.

2. **Колірний пріор** `C = clamp(|mean(ΔRGB)| / 0.6, 0, 1)`.
   - `f_th = 0.6` (підлаштовано під нормалізовані фічі).
   - RGB у датасеті **не нормалізовано** — це сирі `float` з PLY у діапазоні **0-255**.
   - Дивись: `HKCDPairCylinder.cloud_loader` (рядки 241-260) і `Pair.normalise` (рядки 74-90 у `pair.py`) — нормалізуються лише позиції.
   - Для двох сусідніх точок з відмінністю в кольорі навіть на 1 LSB маємо `|mean(ΔRGB)| ≈ 1.0 > 0.6` → **C сатурується до 1 майже всюди**.

3. **Бернуллієва variance** `var_C = C*(1-C) → 0` (при C=1).
   - Клемп: `var_C = max(var_C, _EPS=1e-6)`.
   - `w_C = 1 / var_C ≈ 10⁶`.

4. **Inverse-variance fusion**:
   - `w_D` для D≈0.2 дає `var_D=0.16`, `w_D ≈ 6`.
   - `μ = (w_D·D + w_C·C) / (w_D + w_C) ≈ (6·D + 10⁶·1) / (6 + 10⁶) ≈ 1`.
   - `var_total = 1/(w_D + w_C) ≈ 1/10⁶ ≈ 0`.

5. **Confidence-modulated mask**:
   - `confidence = clamp(1 − var_total/0.25) ≈ 1`.
   - `mask = confidence·μ + (1−confidence)·0.5 ≈ 1·1 + 0 ≈ 1`.

### Що це руйнує

- **Attention mask = константа 1** → `energy = energy * mask = energy` → self-attention працює як без маски (втрачено геометричну модуляцію, яка є у baseline).
- **μ як вхідна фіча = константа 1** → одна "інформативна" фіча на вході знесена в noise channel.
- **σ²_total як вхідна фіча = константа ~10⁻⁶** → друга фіча мертва.
- **Channel 0 в `data.x` = константа 1** (бо new-модель залишає `ones`-канал, тоді як baseline переписує його сигналом `0.5·D + 0.5·C`, що варіюється у [0.5, 1]).

Підсумок: **порівняно з baseline, модель з prior-uncertainty подає на перший KPConv-блок 3 мертві канали (channel 0, μ, σ²) і втрачає attention-mask-модуляцію**. Це повністю узгоджується з невеликим, але систематичним падінням ~0.5-1 п.п. на всіх метриках.

### У baseline таке не відбувається

Baseline `get_mask_v2` (`SIFT_SKP_double_pc.py:406-423`):

```python
input = 0.5 * pos_m_1 + 0.5 * f_m_1
mask = input
```

Фіксована 50/50 фьюз. Навіть з `C ≈ 1` (та сама проблема нормалізації RGB!), результат:

```
input = 0.5·D + 0.5·1 = 0.5·D + 0.5  ∈ [0.5, 1]
```

тобто `mask` усе ще варіюється з D. **Сатурація C у baseline просто знижує динамічний діапазон, а в Bayesian-fusion вона вбиває D повністю** — це фундаментальна різниця, через яку перехід на inverse-variance ламає модель замість того, щоб її покращити.

## Як фіксимо

Три рівні фіксу, від найшвидшого до найбільш правильного. Раджу **застосувати всі три, тоді переучити**.

### FIX 1 — нормалізувати RGB перед `get_mask_v2` (5 рядків)

Робить `f_mat` дійсно в діапазоні ~[0, 1], тому `f_th=0.6` має сенс.

```python
# SiamKPConvWithPriorUncertainty.py, метод get_mask_v2, після рядка 76:
# (одразу після cast у float)
f_1 = f_1 / 255.0
f_2 = f_2 / 255.0
```

**Перевірка ефекту:**
Після фіксу `|mean(ΔRGB)| / 0.6` буде в [0, ~0.4] для типових RGB-відмінностей, тож `C` варіюватиметься нетривіально у [0, 0.7], а не сатуруватиметься в 1.

> ⚠️ Це також варто прокинути в baseline, бо там та сама проблема — але для чистоти експерименту фіксимо лише новий шлях, інакше baseline зміниться і порівняння зруйнується. Якщо хочеш фіксити обидва, тренуй **обидва** заново.

### FIX 2 — пом'якшити inverse-variance вибух (1 рядок)

Замість мікроскопічного `_EPS = 1e-6` (який створює `w = 10⁶`), використати клемп, який обмежує максимальну впевненість одного джерела:

```python
# Було:
_EPS = 1e-6

# Стало:
_EPS = 0.05   # обмежує w_max = 1/0.05 = 20
              # — все ще даємо перевагу впевненим джерелам,
              # але не дозволяємо одному "забивати" інше повністю
```

Це принципово: при `_EPS = 0.05` навіть якщо `C=1` (var=0), `w_C = 20`, а при `D=0.2` (var=0.16), `w_D = 6.25`. Тоді `μ = (6.25·0.2 + 20·1)/26.25 ≈ 0.81` — все ще близько до C, але D дає видимий внесок.

### FIX 3 — не "відкидати" сигнал з channel 0 (3 рядки)

Поточний код тримає `ones` у каналі 0 і додає μ/σ² у кінець. Це поведінка, симетрична baseline, не тримає. Зробити як baseline + додати var як **другий** канал, а не залишати ones-канал константою:

```python
# SiamKPConvWithPriorUncertainty.py, рядки 147-150 — замінити:
data0.x[:, 0] = mu0.squeeze(-1)        # переписуємо ones → μ (як у baseline робиться з 0.5D+0.5C)
data1.x[:, 0] = mu1.squeeze(-1)
data0.x = torch.cat([data0.x, var0], dim=1)   # тепер канал σ²_total — єдина нова фіча
data1.x = torch.cat([data1.x, var1], dim=1)
```

А в моделі-конфізі (`conf/models/change_detection/SiamKPConvWithPriorUncertainty.yaml`):

```yaml
# FEAT змінити з 5 на 4
FEAT: 4   # було 5
# тоді FEAT + 1 = 5 = [μ, R, G, B, σ²_total]
```

> ⚠️ Зміна FEAT змінює форму першого KPConv шару → доведеться **тренувати з нуля** (старі ваги несумісні).

### FIX 4 (опційний) — гібрид з гарантованим non-zero внеском D

Замість чистого inverse-variance, додати floor на ваги пропорційно базовій 50/50 fusion:

```python
# Замість простого w_D = 1/var_D:
w_D_inv = 1.0 / var_D
w_C_inv = 1.0 / var_C

# Нормуємо так, щоб мінімальна вага одного джерела була ≥ 0.5 (50/50 floor)
w_sum_inv = w_D_inv + w_C_inv
w_D_norm = w_D_inv / w_sum_inv
w_C_norm = w_C_inv / w_sum_inv

# Floor: ніяке джерело не отримує менше 30% впливу
ALPHA = 0.3
w_D_final = (1 - 2*ALPHA) * w_D_norm + ALPHA
w_C_final = (1 - 2*ALPHA) * w_C_norm + ALPHA

mu = w_D_final * D + w_C_final * C
```

Тоді inverse-variance дає **впорядкування** (хто впевненіший — отримує більшу вагу), але без виродження. Це більш консервативний дизайн — гарантує, що теоретичні переваги Bayesian-fusion не "вибухнуть" на патологічних випадках.

|---|---|---|
| **F1** | `var_total` як вхідна фіча — слабкий сигнал | Амплітуда σ² ≈ 0.06±0.03 на тлі RGB у [0,1] і μ у [0,1]. KPConv-вагам важко «зачепитись» за фічу з такою низькою std. Без supervision на uncertainty мережа не знає, як її інтерпретувати → ефективно noise channel. |
| **F2** | Single-run noise | Δ = 0.3-1.0 п.п. — у межах варіації одного прогону з одним сидом. Без 3+ прогонів не відрізнити «модифікація погіршує» від «нейтральна». |
| **F3** | Confidence-модуляція маски зменшує контраст | `mask = conf·μ + (1−conf)·0.5` зсуває маску до 0.5 у точках низької довіри → менш різке гасіння attention у unchanged-регіонах. На цифрах: mask.mean ≈ 0.29, mu.mean ≈ 0.24 — маска систематично зміщена до 0.5. Невеликий ефект, але узгоджується зі знаком Δ. |

### Оновлений план експериментів

**Експеримент A — ablation на input-фічі.** Створити 3 варіанти модифікації `forward`:

| Варіант | Input до першого KPConv | Mask до attention | Що перевіряємо |
|---|---|---|---|
| A1 | `[μ, R, G, B]` | `μ` | μ замінює baseline-fusion, нічого нового. |
| A2 | `[ones, R, G, B, var]` | `mask = 0.5·D + 0.5·C` (як baseline) | Окремий ефект σ² як вхідної фічі. |
| A3 | `[ones, R, G, B, μ, var]` (current) | `confidence·μ + (1−confidence)·0.5` | Поточний дизайн (контроль). |
| A4 | `[μ, R, G, B, var]` | `μ` | μ + var без confidence-модуляції маски. |

Якщо A1 ≈ baseline і A4 < A1 — винна **σ²-фіча**.
Якщо A1 ≈ baseline і A3 < A1 — винна **confidence-модуляція маски**.

**Експеримент B — нормалізувати var до confidence.** Замінити сире `var_total` на масштабовану довіру:

```python
# у forward, замість сирого var0:
conf0 = (1.0 - var0 / _MAX_VAR).clamp(min=0.0, max=1.0)
data0.x = torch.cat([data0.x, mu0, conf0], dim=1)
```

Тоді обидва нові канали (μ, conf) знаходяться в [0, 1], рівноправно з RGB. Конфіденс несе ту ж саму інформацію, що σ², але краще параметризовано.

**Експеримент C — переписати канал 0 на μ.** Звичайний FIX 3 з оригінального списку (FEAT: 5→4, `data.x[:, 0] = μ` + cat лише var/conf).

**Експеримент D — багатопрогонне підтвердження (must-have).** 3 прогони з seeds {42, 1337, 2024} для baseline і поточної моделі. Якщо `mean ± std` перетинаються — модифікація **статистично нейтральна**, бажано закрити з висновком «не покращує».

### Рекомендований порядок

1. **D** (запустити 2 додаткові прогони baseline + 2 додаткові prior_unc) — тоді ми знаємо, чи взагалі є що чинити. Можна паралельно з 2-3.
2. **B** (нормалізувати var → conf) — найдешевша зміна коду (2 рядки), має найбільші шанси покращити «м'якший» сигнал.
3. **C** (переписати канал 0) — 1 рядок коду + FEAT зміна → доводиться тренувати з нуля.
4. **A** — повний ablation, якщо B+C не дали ефекту.

### 2. Пороги мають обґрунтування — і воно вбиває підхід за побудовою

`pos_th = 3.0` / `f_th = 0.6` — не магічні константи. Стаття ([IEEE TGRS 2024](https://ieeexplore.ieee.org/document/10620319/)):

> The average distance of SLPCCD, HKCD and URB3DCD-V2 is 0.15, 1.5 and 1.8, so the distance thresholds are set to 0.3, 3.0 and 3.6. The average texture difference of SLPCCD and HKCD is 0.3 and 0.3, so the texture thresholds are set to 0.6.

**Правило: поріг = 2 × середнє по датасету** — середня точка навмисне відображається в `p = 0.5`.

Наслідок: `σ² = p(1−p)` має похідну `1 − 2p`, яка в `p = 0.5` дорівнює **нулю**. Тобто 0.5 — це точка максимуму дисперсії, **мінімуму** ваги (`w = 4`) і при цьому **стаціонарна**. Правило статті садить обидва пріори саме туди → `w_D ≈ w_C` → `μ ≈ (D+C)/2` → **фьюзія вироджується в baseline**.

На заміряних середніх (`D=0.25`, `C=0.30`): `w_D = 5.33`, `w_C = 4.76` → `μ = 0.2736` проти baseline `0.275`. **Різниця 0.002.**

**Порогами це не лікується:** підняти → `p→0` → `σ²→0` → джерело домінує, голосуючи «без змін»; опустити → `p→0.5` → вироджуємось у 50/50. Оскільки `σ²` є функцією самого значення, будь-який поріг нерозривно задає і «де сидить оцінка», і «наскільки їй вірити». Детальний розбір — [prior_mask_math_baseline.md §2](prior_mask_math_baseline.md).

> 💡 Побічно: `pos_th = 1.5` (що відновило б намір статті на реальному розподілі, бо заміряна середня ≈ 0.75 м, а не 1.5 м) зробило б виродження **повним**. Нинішня «поламана» калібровка дає підходу *більше* простору, ніж правильна.

### 3. Нова гіпотеза F4 — фьюзія знищує сигнал суперечності

| # | Гіпотеза | Обґрунтування |
|---|---|---|
| **F4** | Inverse-variance фьюзія знищує сигнал суперечності | `σ²_total = (σ²_D·σ²_C)/(σ²_D+σ²_C) ≤ min(σ²_D, σ²_C)` — тотожність «паралельних опорів». Отже **будь-яке** екстремальне джерело тягне fused-дисперсію до нуля, **незалежно від згоди з іншим**. При `D=1, C=0`: `μ=0.5`, `σ²≈5e-7`, `confidence≈1`, `mask=0.5` — максимальна незгода подається як 0.5 з максимальною впевненістю. Точка «геометрія кричить про зміну, колір мовчить» стає невідрізненною від «нічого не знаємо» (`D=C=0.5` теж → `mask=0.5`), і при цьому σ²≈0 каже мережі «вір цьому». У чесній байєсівській фьюзії незгода двох впевнених джерел мала б **підвищувати** невизначеність. |

Корінь той самий, що й у розділі 2, але з іншого боку: `σ² = p(1−p)` — детермінована функція **самої оцінки**, тож вага кодує «наскільки екстремальне значення», а не «наскільки надійне джерело».

Підтверджено аналітично: `test/test_prior_uncertainty_mask.py` — 6 тестів на закритих формулах (не snapshot). Замкнена форма фьюзії:

```
μ = D·C·(2 − D − C) / [D(1−D) + C(1−C)]
```

У точці `D=1, C=0` це `0/0` зі **шляхо-залежною** границею, тож `mask=0.5` там є артефактом `_EPS`-регуляризації, а не справжнім значенням.

Побічний результат тих же тестів: `_MAX_VAR = 0.25` — константа нормалізації **вдвічі завелика**. Максимум fused-дисперсії становить `0.125` (досягається при `D=C=0.5`), а не 0.25, бо `w ≥ 4` для кожного джерела → `w_sum ≥ 8`. Отже `confidence = 1 − σ²/0.25` фізично **не може впасти нижче 0.5**, а `.clamp(min=0.0)` — недосяжна гілка.

Наскільки F4 б'є по реальних даних — **невідомо**: `D.sat ≈ 0.02-0.13`, `C.sat ≈ 0.003`, тож точних `D=1, C=0` мало. Ефект працює й на м'якших розбіжностях, але слабше. Щоб перевірити, треба додати D і C у `_dumped_io` (зараз там лише μ/var/mask) і подивитись розподіл `|D−C|`.
